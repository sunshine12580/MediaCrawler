# 题干解析规范：字段来源与解析算法

## 0. 这份文档给谁用、边界在哪

给另一个独立编写的采集程序用，让它抓组卷网（zujuan.xkw.com）题目列表页时，
按**和本项目完全一致的算法**解析字段、产出兼容格式的数据。目标不是"抓到差不多
的信息"，而是"字段值和本项目自己抓出来的一模一样"——这样两边的数据合并起来
时不会出现"同一个字段两种口径"的问题，而且可以直接用本项目现成的工具继续处理
（重新解析、入库、离线渲染）。

**只覆盖题干，范围到此为止，以下明确不包含：**

| 不包含 | 为什么 |
|---|---|
| 登录/扫码/账号态 | 题目列表页和题干本身**不需要登录**，游客身份就能拿到这份文档要求的全部字段 |
| 答案抓取（`checkQuesParse` 接口、答案图、`answer_status` 等） | 答案是另一条独立的线，走的是另一个接口，和题干抓取的字段解析没有关系 |
| 离线解析后续步骤（HTML→Markdown/纯文本转换、图片下载与本地化、OCR、选项拆成单独的表、图片去重登记） | 这些都是吃"已经入库的 `stem_html`"做二次加工，本项目自己的离线脚本会处理，**不需要另一个程序做**，也不需要它产出 Markdown/纯文本版本 |

**只需要产出两样东西**：

- **A) 原始快照**：一行一道题的 JSONL，保留卡片的完整原始 HTML + 已解析字段，供以后任何时候离线重新解析（解析规则改了不用重新抓）
- **B) 结构化字段**：`questions` 表的题干相关列，加 `question_knowledge` / `question_sources` 两张多对多关联表

## 1. 数据从哪来：一道题在页面上长什么样

列表页一页 10 道题，每道题是一个独立的卡片区块。卡片内几个关键区域：

| 区域 | 参考定位方式 | 拿到什么 |
|---|---|---|
| 卡片本身 | `div.tk-quest-item.quesroot`（这是本项目用的选择器，另一个程序如果 DOM 结构不同，找等价的定位方式即可，字段含义不变） | 属性 `questionid`（题目 ID）、`bankid`（题库编号） |
| 题干内容区 | `div.exam-item__cnt` | 这个元素的 **innerHTML**（含 `<img>` 公式图/插图标签，如果是选择题还包含选项 `<table name="optionsTable">`） |
| "加入试题篮"按钮 | `a[data-btn-type='quesAdd']` | 见下表，**这是个真按钮，只读它身上的属性，绝对不要点击**——点了会把题目真的加入购物车 |
| 完整题型说明文字 | 卡片正文里第一个 `span.info-cnt`（在 `span.addi-info` 下） | 例如 `"解答题-计算题"`——**这是唯一带子类型的地方**，按钮属性上只有大类 `"解答题"` |
| 标签角标 | `span.tag`（可能 0 个/1 个/多个） | 文字含"名校"/"真题"关键字则命中对应标记 |
| 来源试卷链接 | `div.more-src-links a`（可能多个，卡片上写着"N 卷引用"） | `href` 形如 `/2p3412301.html`，`title` 属性是试卷全名 |
| 知识点标签 | `div.knowledge-list a`（可能多个） | `href` 形如 `/czsx/zsd4713`，链接文字是知识点名称 |
| 底部信息条 | 若干带 `title` 属性的 `span` | 其中一条文字形如 `"23次组卷"` |

"加入试题篮"按钮身上的属性（**这是本项目里绝大多数结构化字段的来源，优先级高于任何正文文字**）：

| 属性名 | 含义 | 备注 |
|---|---|---|
| `qyid` | 题型码 | 如 `1101` |
| `qyname` | 题型名（大类） | 如 `"单选题"`；解答题这里只给大类，不给子类型 |
| `qdid` | 难度码（5 档） | `1`容易 `2`较易 `3`适中 `4`较难 `5`困难 |
| `qdname` | 难度名（5 档） | 和 `qdid` 对应 |
| `qdvalue` | 得分率 | 字符串数字，如 `"0.95"`，直接是数字，不用从文字里抠括号 |
| `categoryid` | 所属章节 ID | |
| `categoryname` | 所属章节名 | 如 `"有理数"` |
| `questitle` | 来源试卷全名 | 如 `"湖南湘潭江声实验学校2025-2026学年七年级上学期期中考试数学试题卷"` |
| `titleabbreviation` | 来源三段式简称原串 | 如 `"25-26七年级上—湖南湘潭—期中"`，第 2.6 节详细讲怎么拆 |
| `childnum` | 小问数（可选） | 只进原始 JSONL，**不对应任何 DB 列**（见 2.7 节说明） |

## 2. 逐字段解析算法

### 2.1 题目 ID / 题库编号

直接读卡片属性，不做任何转换：

- `question_id` ← `questionid` 属性
- `bank_id` ← `bankid` 属性（初中数学固定是 `"2"`，但**要照抓，不要写死**——万一切到其它学科/学段这个值会变）

**抽不到 `question_id` 时不要抛异常**，返回这道题 `question_id = null`（其余字段照常尝试解析），让调用方能看到"这一页 10 张卡片里有几张没 ID"。这是这类抓取任务最难发现的故障——不报错，只是数量悄悄变少。

### 2.2 题干正文 `stem_html` / `stem_text`

1. 取 `div.exam-item__cnt` 的 innerHTML（保留原始标签，包括里面的 `<img>`）→ 这是 `stem_html` 的原料
2. 同一个元素取纯文本（HTML 解析库自带的取纯文本方法即可，会自动处理实体转义）→ 这是 `stem_text` 的原料
3. **两者都要剥掉开头的位置号**，见下面的算法

**位置号剥离**（这一步不能省，否则重复抓取时会产生大量"内容变了"的假阳性，详见第 5 节）：

题干开头常带一个形如 `"1 . "`（数字 + 空格 + 点 + 空格）的序号，**这不是题目内容，是这张卡片在当前列表页上的第几个位置**（一页 10 道，序号就是 1~10）。同一道题挂在不同知识点、出现在不同页面时，这个序号每次都不一样，必须在解析这一步就剥掉，不要存进 `stem_html`。

正则（Python 语法，其它语言用等价写法即可）：

```
^\s*\d{1,3}\s+[.．、]\s+
```

只替换一次（字符串开头）。**关键是数字和点两边都必须有空白**——这是为了避免把 `"3.14 是圆周率"` 这种题干误剥成 `"14 是圆周率"`。宽松写法（比如 `\d+\s*\.`）看起来更"包容"，实际是在制造静默的数据损坏。

### 2.3 题型

- `qtype_code` ← 按钮属性 `qyid`
- `qtype` ← 按钮属性 `qyname`（大类，如 `"解答题"`）
- `qtype_full` ← 卡片正文第一个 `span.info-cnt` 的文字（完整题型，如 `"解答题-计算题"`）——**这是唯一带子类型的地方**，按钮属性没有，所以这一步不是"按钮取不到才兜底"，是**每次都要读**
- `qtype_sub` ← 由 `qtype_full` 拆分得到：按 `-`/`－`/`—` 这三种横线切开，取第 2 段。只有解答题（拆出计算题/作图题/应用题/证明题/问答题）和多选题（拆出"2个答案"/"3个答案"/"4个答案"）会拆出东西，其余题型 `qtype_full` 本身就没有横线，`qtype_sub` 留空

  正则：`[-－—]`，用它 split `qtype_full`，第 0 段是大类、第 1 段（如果存在）是子类型

### 2.4 难度

- `difficulty_code` ← 按钮属性 `qdid`（5 档：1~5）
- `difficulty` ← 按钮属性 `qdname`（5 档：容易/较易/适中/较难/困难）
- `score_rate` ← 按钮属性 `qdvalue`，转成浮点数。**转换失败就整个字段留空，不要塞 0**——0 是一个合法的得分率，不能拿它当"没取到"的占位值
- `difficulty_band` ← 由 `score_rate` **重新计算**出的 3 档难度，规则：

  ```
  score_rate > 0.8   → "容易"
  score_rate > 0.5   → "适中"
  0 < score_rate ≤ 0.5 → "困难"
  score_rate 取不到、或不在 (0, 1] 区间 → 留空
  ```

  **★ 这一档和 `difficulty_code`/`difficulty` 是完全独立的两套编码，数字会撞车，绝对不能混用**：卡片给的 `qdid=2` 含义是"较易"，而如果站点筛选功能用的是 3 档编码，`2` 在那套里含义是"适中"。两套都要存，`difficulty_band` 是本项目自己按得分率算出来对齐 3 档口径的，不是站点原始给的。

### 2.5 来源试卷全名 / 章节

- `source`（来源试卷全名）← 按钮属性 `questitle`
- `title_abbr`（三段式简称原串）← 按钮属性 `titleabbreviation`，**原串照抄，不要自己先做任何处理**，拆分算法见 2.6
- `category_id` / `category_name` ← 按钮属性 `categoryid` / `categoryname`

### 2.6 `title_abbr` 三段式解析（核心算法）

`titleabbreviation` 长这样：

```
25-26七年级上—湖南湘潭—期中
└──┬────────┘ └──┬──┘ └┬┘
 学年+年级+学期   省+市   来源类型
```

**分隔符是全角破折号 `—`（U+2014）**。注意页面上*显示*给人看的那个串用的是中点 `·`，和这个属性里的值不是同一个字符，**解析要用这个属性的原值，不要用显示文字**。实操时两种分隔符都识别（正则 `[—·]`），万一站点哪天把属性也换成显示串，解析不至于全废。

按分隔符切开后最多 3 段，**从右往左解析**（哪一段缺失都要能独立处理，不要假设一定是 3 段齐全）：

**第 3 段：来源类型**——直接原样存成 `source_type`，如 `"期中"`。**这个词表比任何筛选下拉框里给的选项都多**（实测出现过"模拟预测"这种筛选框里没有的取值），所以不要拿一个固定词表去校验它，校验不过不代表解析错了，原样存字符串就对了。

**第 2 段：省 + 市**——比如 `"湖南湘潭"`，**省市之间没有任何分隔符**，只能靠一张省份名称表做**最长前缀匹配**：

1. 准备一张全国 31 个省级行政区中文名 → 国标行政区划码的表（北京/天津/河北/山西/内蒙古/辽宁/吉林/黑龙江/上海/江苏/浙江/安徽/福建/江西/山东/河南/湖北/湖南/广东/广西/海南/重庆/四川/贵州/云南/西藏/陕西/甘肃/青海/宁夏/新疆，另有一个特殊值 `"全国"`），**按名称长度从长到短排序**
2. 依次尝试这个第 2 段字符串是不是以某个省份名开头，命中第一个就是这道题的省份，**必须按长度降序试**——否则"内蒙古"会被"内蒙"这种更短的误判先吃掉（如果你的省份表里凑巧没有"内蒙"这种短名，这一步风险较小，但仍建议养成按长度降序的习惯）
3. 命中省份后，把省份名从字符串开头去掉，剩下的部分就是市名。**直辖市（北京/上海/天津/重庆）例外**：不再取市名，`city` 留空——不要编造一个市名出来
4. 都匹配不到省份名时：`province` 留空，`city` 存整个原始字符串——不要丢数据

**第 1 段：学年 + 年级 + 学期**——这一段有三种形态，必须都能处理：

```
25-26七年级上   学年区间（两位数） + 年级 + 学期
2022七年级上    完整年份（四位数） + 年级 + 学期
2022           只有年份
```

正则（Python 语法，命名组）：

```
^\s*(?:(?P<y1>\d{2,4})\s*-\s*(?P<y2>\d{2,4})|(?P<y>\d{4}))?
\s*(?P<grade>[一二三四五六七八九十]+年级)?
\s*(?P<term>[上下])?\s*$
```

- 命中 `y1`+`y2`（区间形式）：两位数按下面规则转四位数，年份区间存成 `"2025-2026"`（`school_year` 字段），`year` 取**起始年**（`2025`）
- 命中单独的 `y`（已经是四位数）：直接存进 `year`，`school_year` 留空
- `grade` 命中就是 `grade_level`（如 `"七年级"`）
- `term` 命中的是单字"上"或"下"，存的时候拼成 `"上学期"`/`"下学期"`

两位年份转四位数的规则：`n < 60` 时当 `2000+n`，`n ≥ 60` 时当 `1900+n`（题库不会出现 1960 年代之前的题，这个分界线怎么划都安全）。

**解析不出来的字段一律留空，不要抛异常**——少一个维度只是查询时少一个筛选面，让整道题入库失败的代价更大（这道题可能是翻了几十页才抓到的）。

### 2.7 其余标量字段

| 字段 | 来源 | 算法 |
|---|---|---|
| `year`（最终写库的那个） | 优先用 2.6 节从 `title_abbr` 解析出的 `year`；解析不出来时，从 `source`（来源试卷全名）里用正则 `20\d{2}` 抠一个四位年份兜底 | 两条路都取不到就留空 |
| `used_count` | 底部信息条里形如 `"23次组卷"` 的那个 span | 正则 `(\d+)\s*次组卷` |
| `is_famous_school` | 标签角标数组 | 数组里任意一项文字包含"名校"→ `1`，否则 `0`（不是留空，是明确写 `0`） |
| `is_real_exam` | 标签角标数组 | 同上，含"真题"→ `1`，否则 `0`。**★ 这个和 `source_type == "中考真题"` 是两回事**——后者来自 `title_abbr` 第 3 段（这份卷是什么类型），前者是卡片上单独的一个角标，两者互不影响，都要存 |
| `knowledge_id`（DB 单值列） | 这道题全部知识点标签里的**第一个**的 ID | 只是给一个方便索引的主键位，真正筛题要用关联表 `question_knowledge`（见 2.9），不要只存这一列就丢了其余知识点 |
| `knowledge_tags`（DB 单值列） | 这道题全部知识点标签的**名称**，存成 JSON 数组字符串 | 仅供人工查看用，不建索引，不要拿它筛题 |
| `paper_id` | 来源试卷列表（可能多个）里的**第一个**的 paper_id | 同上，只是给个主来源，完整列表进 `question_sources` |
| `childnum` 属性 | 只进原始 JSONL 的 `sub_question_count` 字段 | **★ 不对应任何 DB 列**——DB 里虽然有个名字很像的 `sub_question_cnt` 列，但那一列是本项目离线阶段另外算的（数题干文字里 `(1)(2)(3)` 这种小问标记），跟这个属性完全是两回事，不要把它俩接起来 |

### 2.8 公式图 / 插图拆分

题干里的 `<img>` 标签既可能是公式图也可能是插图，**属性上完全一样，唯一能区分的是 URL**：URL 路径含 `/Upload/formula/` 的是公式图，否则是插图。逐个遍历 `stem_html`（或题干区元素）下的全部 `<img>`：

- 是公式图 → 记进 `formulas` 数组，每项 `{url, img_key, latex, latex_from}`
  - `img_key`：URL 去掉查询参数后的文件名（不含扩展名）。**公式图的文件名本身就是站点算好的内容哈希**（一个 32 位十六进制串），同一个公式不管出现在哪道题里 URL 完全一样，这个值天然就是去重键，不用自己下载图片再算哈希
  - `latex` / `latex_from`：试着从 `<img>` 的 `alt`/`title`/`data-latex` 这几个属性里读 LaTeX 源码，**绝大多数情况下读不到**（这是本项目 2026-08-17 实测的结论，只是留着这条路，万一站点哪天开始在属性里给 LaTeX 就白捡）。读不到就留空——**这一步不做 OCR，只是尝试性地读属性，OCR 是离线阶段的事，不在这份文档范围内**
- 不是公式图 → 记进 `images` 数组，每项 `{url}`

这一步只是**分类记录**，不下载、不识别，纯粹是给 JSONL 提供这两个数组，方便以后离线处理时知道"这道题原本有几张公式图、几张插图，URL 分别是什么"。

### 2.9 知识点 / 来源试卷（多对多）

**知识点**：遍历卡片上全部知识点标签（可能 0 个到 10 个不等），每个标签给一个 `{id, name}`：
- `id`：从链接 `href` 用正则 `(zsd\d+)` 抠出来
- `name`：链接的文字内容

**来源试卷**：遍历卡片上全部来源试卷链接（可能多个，卡片文案写的是"N 卷引用"），每个给一个 `{paper_id, bank_id, title, url}`：
- 从 `href`（形如 `/2p3412301.html`）用正则 `/(\d+)p(\d+)\.html` 抠出 `bank_id`（第一个数字）和 `paper_id`（第二个数字）
- `title` 优先取链接的 `title` 属性（全名），取不到才用链接文字（可能是缩略显示）
- **同一套试卷可能在卡片上出现两次**（一次在顶部摘要、一次在展开区），按 `paper_id` 去重，不要重复记

这两组数据既要整进原始 JSONL 的 `knowledge`/`sources` 数组，也要各自拆成 `question_knowledge`/`question_sources` 两张关联表的多行（数组第几个元素就是关联表 `ord` 列的值，从 0 开始）。

## 3. 输出格式：精确到每个字段

### 3.1 原始 JSONL——每行一条完整记录

**这个格式不能自己改**，必须严格照抄下面的 key 名和结构，这样产出的文件可以直接放进本项目的 `data/raw/` 目录，用现成工具重新解析：

```json
{
  "kind": "question",
  "question_id": "35030941",
  "bank_id": "2",
  "stem_html": "（剥过位置号的题干 HTML，含 <img> 标签）",
  "url": "抓这道题时用的完整列表页 URL",
  "meta": {
    "qtype_code": "1101", "qtype_name": "单选题",
    "difficulty_code": "1", "difficulty_name": "容易",
    "difficulty_band": "容易", "score_rate": 0.95,
    "category_id": "4687", "category_name": "有理数",
    "source_full": "湖南湘潭江声实验学校2025-2026学年七年级上学期期中考试数学试题卷",
    "source_short": "25-26七年级上—湖南湘潭—期中",
    "sub_question_count": "1",
    "year": 2025,
    "title_abbr": "25-26七年级上—湖南湘潭—期中",
    "school_year": "2025-2026", "grade_level": "七年级", "term": "上学期",
```

## 4. 几条不能省的纪律

1. **抽不到某个字段不等于程序出错**——找不到插图、找不到来源试卷、知识点标签一个都没有，都是正常情况，对应字段/数组留空即可，**不要抛异常中断整道题的解析**。一道题解析失败，只应该影响这一道题，不该拖累这一页其它 9 道。

2. **抽到了 `question_id` 却没抽到 `stem_html`，这个不算正常，要单独标记出来**——这说明抽取环节本身出了问题（比如页面结构变了、某个选择器过期了），不是"这道题没有题干"。这种半成品**不要直接当正常数据存进去**，应该单独记一条警告日志（带上 `question_id`），方便回头排查是不是选择器失效了。本项目 2026-08-18 真实踩过这个坑：一次选择器失效，200 多道题的 ID 抓到了但题干和其它字段全是空的，程序没有任何报错提示，直接把空数据存进了库。

3. **对不上的字段留空，不要编造**——比如解析不出省份、拆不出子题型，都应该是"这个字段没有值"，而不是拿一个猜测值填进去。宁可字段是空的，也不要是错的（空值容易被后续发现和修，错值会一直安静地待在那里）。

4. **同一次抓取里出现的重复元素要去重**——比如一道题的来源试卷在卡片上出现了两次（一次摘要一次展开区），按 `paper_id` 去重后再写，不要在关联表里插入两条一样的行。

## 5. 重复抓取时的处理方式（不是"解析"，但直接影响入库逻辑）

如果这个题目 ID **在库里已经存在，而且已有的 `stem_html` 不是空的**，正常情况下应该**直接跳过，不重新写这道题的任何字段**——不要用抓到的新内容和库里已有的内容做比对来决定"要不要更新"。

原因：`stem_html` 开头的位置号（2.2 节剥掉的那个"1 . "）虽然在存库之前就已经剥掉了，但即便剥掉，同一道题在不同知识点、不同页码上抓到的其它上下文信息（比如这次记录的 `list_url`）天然就会不一样——如果拿"内容有没有变"当判据来决定要不要重写，会把绝大多数"其实没变"的题误判成"变了"，白白重复写入。**已存在就跳过**是更简单也更安全的规则。

例外：如果库里这道题的 `question_id` 存在，但 `stem_html` 是空的（说明是上一轮的半成品，见第 4 节第 2 条），这次应该把它**补上**（更新这一行，而不是新插入一行）。
